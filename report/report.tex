\sectiontitle{1. Project objective}
Build a small, production-style Calculator REST API in Java and connect it to an automated delivery pipeline. A GitHub push should trigger Jenkins to compile and test the application, package and publish a Docker image, deploy the Compose stack, and verify service health. The assessment emphasizes DevOps engineering rather than mathematical complexity. The scope ends at Compose-based deployment.

\sectiontitle{2. Application and verification}
\subhead{REST API}
\begin{tabularx}{\linewidth}{@{}>{\bfseries}p{1.55cm} p{5.1cm} X@{}}
\rowcolor{blue!85!navy}\textcolor{white}{Operation} & \textcolor{white}{\textbf{Endpoint}} & \textcolor{white}{\textbf{Response / behaviour}}\\
Add & \texttt{/api/v1/add?a=\&b=} & Returns \texttt{a + b} as JSON.\\
Subtract & \texttt{/api/v1/subtract?a=\&b=} & Returns \texttt{a - b} as JSON.\\
Multiply & \texttt{/api/v1/multiply?a=\&b=} & Returns \texttt{a * b} as JSON.\\
Divide & \texttt{/api/v1/divide?a=\&b=} & Returns \texttt{a / b}; zero divisor gives HTTP 400 and structured error JSON.\\
Health & \texttt{/actuator/health} & Spring Actuator UP/DOWN probe used by Compose.\\
\end{tabularx}

Successful calculations return \texttt{operation}, \texttt{a}, \texttt{b}, and \texttt{result}. Missing or non-numeric inputs and division by zero return HTTP 400 with timestamp, status, message, and request path. The Spring Boot application is Maven-based and produces an executable JAR.

\subhead{Test coverage}
The suite contains 8 JUnit 5 service tests and 7 MockMvc tests covering all four operations, negative and decimal values, missing/invalid inputs, and division by zero. \texttt{mvn test} produces Surefire JUnit XML; Jenkins publishes those reports and fails a build on test failures. Final local run: 15 tests, 0 failures, 0 errors.

The declarative Jenkinsfile runs six stages: Checkout, Build (\texttt{mvn clean package -DskipTests}), Test (\texttt{mvn test}), Docker Build (build-number and \texttt{latest} tags), Push (Jenkins-managed Docker Hub credential), and Deploy. The repository is configured for GitHub push events through the reserved ngrok domain; \texttt{githubPush()} is the Jenkins trigger. The webhook endpoint is \texttt{https://unstaffed-disperser-tweezers.ngrok-free.dev/github-webhook/}. Build 10 was verified with cause “Started by GitHub push by KaushalrajPuwar”; the GitHub push delivery returned HTTP 200. The tunnel must be running for GitHub to reach the locally hosted Jenkins instance. For a later demo, run \texttt{brew services start jenkins-lts}, then start \texttt{ngrok http 8080 --url https://unstaffed-disperser-tweezers.ngrok-free.dev} in a terminal and leave it open.

\sectiontitle{4. Containerization, deployment and evidence}
The multi-stage Dockerfile compiles the JAR in a Maven/JDK 21 build stage, then copies only the artifact into a slim JRE Alpine runtime. The runtime uses a non-root \texttt{app} account and exposes port 8080. The image is available publicly as \texttt{kaushalrajpuwar/arithmos-calculator} on Docker Hub.

Docker Compose starts two services on a shared network: the calculator API (host port 8081) and an Nginx reverse proxy (host port 8082). The app has an Actuator health check, restart policy, and configurable port environment variable; Nginx waits for the app to become healthy. A clean-slate Compose run and a standalone \texttt{docker run} were both verified.

\sectiontitle{5. Challenges faced and solutions}
\begin{itemize}
\item \textbf{JDK mismatch in Jenkins.} The machine default resolved to Java 27 although the project targets Java 21; Mockito inline mocks failed in that runtime. \textit{Resolution:} pinned \texttt{JAVA\_HOME} and \texttt{PATH} to the installed Java 21 runtime; the full suite then passed.
\item \textbf{Compose container-name collision.} Manual test containers remained when Jenkins deployed from a different workspace. \textit{Resolution:} made deployment repeatable by running \texttt{docker compose down --remove-orphans} before \texttt{up -d}, followed by a health and proxy check.
\item \textbf{Public webhook reachability and signature validation.} GitHub cannot deliver to localhost, and Jenkins initially rejected webhook signatures because the secret was not referenced as a Jenkins credential. \textit{Resolution:} used the reserved ngrok domain, stored a dedicated secret in Jenkins Credentials, selected SHA-256 verification, and confirmed GitHub ping/push deliveries return HTTP 200.
\item \textbf{Email delivery.} Jenkins initially attempted an unavailable local SMTP service. \textit{Resolution:} configured Gmail SMTP with TLS and stored the app password in Jenkins configuration, then verified the success notification in the inbox.
\end{itemize}

\sectiontitle{6. Conclusion}
The project delivers a working, repeatable path from a GitHub push to a tested release and health-verified deployment. The Calculator API has four operations, structured input errors, and an Actuator probe. Its 15-test suite runs in Jenkins, which builds and publishes versioned Docker images, deploys the two-service Compose stack, verifies the API through Nginx, and sends build notifications. GitHub push events reach Jenkins through the configured ngrok webhook. The public source and image remain available at the links below.
